# SDD-06: Phase N — Re-backfill with Real Classifier

**Date:** 2026-09-26
**Project:** FoxyBear Harness Phase N (`development/foxybear`)
**Status:** Draft (pending independent audit + human gate)
**Master:** `260926_fbh-phase-n_sdd-00-master.md`
**Depends on:** `sdd-05` (Wire into capture — the real SDD-04 pipeline is wired into the post-turn hook; transitive: `sdd-04` Gate-extract-classify pipeline, `sdd-03` Circular buffer, `sdd-01` Jev provider, `sdd-02` Gemini provider)

Phase N's re-backfill. The Phase M backfill script (`packages/fbh/script/backfill-hypergraph.ts`) ran against all 1,269 sessions and produced ~224k nodes: 85k deterministic (ACTION/ERROR/MESSAGE from `TraceIngestor`) and 139k stub-generated (ENTITY/MEMORY/PROCEDURE from the regex extractor labeled `source_path: "llm"`). The 139k stub nodes are noise — the master §Problem being solved documents 138k noise ENTITY nodes ("The", file paths) and 4 MEMORY nodes from regex patterns. This spec re-runs the backfill with the real SDD-04 classifier: delete the 139k stub nodes, preserve the 85k deterministic nodes (CC-1 no data loss), re-ingest all 1,269 sessions through the SDD-04 gate-extract-classify pipeline, write idempotent markers per DB, run pre-flight verification (TraceIngestor determinism check + SurrealDB snapshot), log progress, and resume from the last checkpoint on interruption.

The existing backfill script directly calls `EntityExtractor.extract` and `MemoryExtractor.extract` (`backfill-hypergraph.ts:230-231`) — the Phase M stubs that return regex results labeled `source_path: "llm"` (`entity.ts:82`, `memory.ts:63` per SC-1's stub table; the third stub at `hyperedge.ts:60` is not called by the backfill script but is replaced by SDD-05 in the production path). SDD-05 wires the real `classify` pipeline into the post-turn hook, but the backfill script bypasses the post-turn hook and calls the extractors directly. This spec updates the backfill script to invoke `classify(input: ClassifyInput)` at `src/memory/classify/pipeline.ts` (the single entry point per SC-1 — the pipeline owns the store and the buffer; the script does NOT call `persistMemories`/`persistEntities`, `SurrealHypergraphBackend.store`, or `Buffer.add`/`Buffer.getContext` directly; CC-2 stub replacement, not addition), adds the delete-stub step, and adds the pre-flight, progress, and resume machinery.

## WHAT

### Pre-flight verification

1. **WHEN** the re-backfill script starts, it **SHALL** run four pre-flight checks before any delete or write: (a) **TraceIngestor determinism check** — pick the oldest session in `SessionTable` by `time_created`, re-ingest it through `TraceIngestor.ingest` against a throwaway backend, and assert the emitted ACTION/ERROR/MESSAGE node count matches the stored count for that session within ±0% (exact match — `TraceIngestor` is deterministic by construction per SDD-05 W-1/W-2/W-3; the count is the proxy for content-determinism since the ULIDs differ but the content/types are identical); (b) **SurrealDB snapshot** — export the current `node` and `hyperedge` tables to `~/.local/share/foxybear/rebackfill-snapshot-<dbname>-<ISO>.json` (where `<dbname>` is the basename of the current SQLite DB with the `.db` suffix stripped, and `<ISO>` is the ISO-8601 timestamp with colons replaced by dashes) via `graph.run("SELECT * FROM node;")` + `graph.run("SELECT * FROM hyperedge;")` + `Bun.write`; (c) **session count check** — assert `SessionTable` row count is ≥ 1 (the master's 1,269 figure is the known corpus size, not a hard gate — the script processes whatever sessions exist); (d) **classifier availability check** — assert `classify` is importable from `src/memory/classify/pipeline.ts` (SC-1) and the Jev (gate) + Gemini (extract) providers respond to a 1-turn smoke call (gated on `memory.extraction.external_opt_in = true` per SC-2 default; if `false`, the script **SHALL** exit non-zero with a message pointing the user at `external_opt_in` unless `--allow-regex-only` is passed). If any pre-flight check fails, the script **SHALL** exit with a non-zero code BEFORE any delete or write, and **SHALL** log the failing check name + the snapshot path (if written).

2. **WHEN** the SurrealDB snapshot (req 1b) is written, the script **SHALL** assert the snapshot file is non-empty and parses as JSON with a `node` array, a `hyperedge` array, and a `metadata` object containing `{ db, surrealdb_version, session_count, node_count, hyperedge_count, exported_at }`. The snapshot **SHALL** be a full export (every row, every field) — not a sampled subset. The snapshot path **SHALL** be recorded in the marker (req 11) and in the resume checkpoint (req 14) so a restore can locate it. The script **SHALL NOT** proceed to the delete step until the snapshot assertion passes (the snapshot is the restore point — a corrupt snapshot means a delete is unrecoverable).

### Delete stub nodes (CC-1)

3. **WHEN** the pre-flight checks pass, the script **SHALL** run the delete step: hard-delete every `node` record with `node_type IN ("ENTITY", "MEMORY", "PROCEDURE")` from the `node` table via a single SurrealQL statement `DELETE FROM node WHERE node_type IN ["ENTITY", "MEMORY", "PROCEDURE"];` (or a batched transaction if the 139k-row delete exceeds SurrealDB's transaction size limit — batch size 10,000 rows per transaction). The script **SHALL NOT** delete any `node` with `node_type IN ("ACTION", "ERROR", "MESSAGE")` (CC-1 deterministic preservation). The script **SHALL NOT** use the per-node `SurrealHypergraphBackend.deleteNode` API (`surreal-hypergraph-backend.ts:628`) for the bulk delete — 139k per-node round-trips would take hours; the bulk `DELETE WHERE node_type IN [...]` statement is the only acceptable path.

4. **WHEN** the stub-node delete (req 3) runs, the script **SHALL** also delete the corresponding `hyperedge_members` rows for the deleted node IDs (`DELETE FROM hyperedge_members WHERE node_id NOT IN (SELECT node_id FROM node);` — the subquery returns the surviving node IDs, so the members linked to deleted stub nodes are removed), and **SHALL** delete orphaned `hyperedge` records whose `node_ids` array is empty after the stub-node delete (`DELETE FROM hyperedge WHERE id NOT IN (SELECT hyperedge_id FROM hyperedge_members);` — the orphaned-hyperedge delete runs AFTER the member delete, so the emptiness check reflects the post-delete state). Non-orphaned hyperedges (those still linking to ≥ 1 surviving deterministic node) **SHALL** be preserved with their `node_ids` array intact (the deterministic node IDs are unchanged — the stub node IDs in the array are simply orphaned references that no longer resolve; SurrealDB tolerates dangling record IDs in array fields, so the hyperedge is not corrupted, just has stale refs).

5. **WHEN** the delete step completes, the script **SHALL** append a `REBACKFILL_DELETE` event to the `event` table (append-only audit log per SDD-03) recording `{ deleted_nodes: { ENTITY: number, MEMORY: number, PROCEDURE: number }, deleted_hyperedges: number, deleted_members: number, snapshot_path: string, at: ISO8601 }`. The per-type deleted counts **SHALL** be asserted against the snapshot's per-type counts (req 2) — the deleted count per type **SHALL** equal the snapshot's count per type within ±0% (exact match). If the deleted count diverges from the snapshot, the script **SHALL** fire abort A_N (restore from snapshot via the existing `m0-abort.ts` restore path, halt) and exit non-zero. The `REBACKFILL_DELETE` event is the audit trail — the stub nodes are hard-deleted, not soft-deleted, because they have no audit value (soft-delete would leave 139k DELETED records bloating the table and future queries).

### Keep deterministic nodes (CC-1)

6. **WHEN** the delete step completes, the script **SHALL** assert that the count of `node` records with `node_type IN ("ACTION", "ERROR", "MESSAGE")` is unchanged from the snapshot's pre-delete count (req 2). The deterministic-preservation check **SHALL** query the `node` table directly: `SELECT count(), node_type FROM node WHERE node_type IN ["ACTION", "ERROR", "MESSAGE"] GROUP BY node_type;` and compare per-type counts to the snapshot. If any deterministic-type count changed (ACTION ≠ 65k, ERROR ≠ 2k, MESSAGE ≠ 18k — or the actual snapshot counts if the corpus differs), the script **SHALL** fire abort A_N (restore from snapshot, halt) and exit non-zero. This is the CC-1 gate: no data loss. The deterministic nodes are preserved, not re-ingested — `TraceIngestor.ingest` is NOT called in the main re-ingest loop (req 7) because re-emitting would produce new ULIDs and duplicate the 85k records, violating CC-1. `TraceIngestor.ingest` is called only in the pre-flight determinism check (req 1a) against one fixture session against a throwaway backend, never against the live `node` table.

### Re-ingest with classifier (CC-2, SDD-04)

7. **WHEN** the re-ingest step runs, the script **SHALL** iterate every session in `SessionTable` ordered by `time_created` ascending (oldest first — matches the production chronological order so the SDD-03 circular buffer is populated correctly across turns), and for each session **SHALL** group the session's messages into turns (a turn = one user message + the subsequent assistant messages + tool calls, up to the next user message — the existing `MessageV2.stream(s.id).reverse()` pattern at `backfill-hypergraph.ts:185` is replaced by a per-turn grouping that splits on user-message boundaries) and for each turn **SHALL** invoke `classify(input: ClassifyInput)` at `src/memory/classify/pipeline.ts` (SC-1 — the single entry point). The pipeline **SHALL** be invoked via the same function SDD-05 wires into the post-turn hook (the production code path), NOT a parallel re-backfill-only classifier path (CC-2). The `ClassifyInput` **SHALL** be constructed per turn as `{ sessionID, text, project_id, persona }` (SC-1); the pipeline returns `ClassifyResult` (`{ stored, skipped, errors }`). The existing `EntityExtractor.extract` and `MemoryExtractor.extract` calls at `backfill-hypergraph.ts:230-231` are REMOVED — `classify` replaces them. The existing `TraceIngestor.ingest` call at `backfill-hypergraph.ts:208` is REMOVED from the main loop (deterministic nodes preserved per req 6) — it survives only in the pre-flight determinism check (req 1a).

8. **WHEN** the re-ingest step invokes `classify(input)`, it **SHALL** respect: (a) the gate threshold (`memory.extraction.gate_threshold`, default 0.5 per SC-2) — turns scoring below the threshold skip extraction (`classify` gates via `Jev.noul`, returning `enriches_future ≤ 0.5` → skip; SC-1 step 2); (b) the circuit breaker (CC-9: Jev/Gemini latency > 3s for 5 consecutive calls, or error rate > 5%, falls back to regex-only extraction — `classify` enforces this internally; the script **SHALL** log each circuit-breaker fire and each fallback invocation in the marker, req 11); (c) the rate limits (CC-5: Jev 10 req/sec, Gemini 5 req/sec — `classify` enforces these internally; the script **SHALL** not bypass them by parallelizing `classify` calls — backfill calls `classify` sequentially per turn, or with a concurrency cap that respects the rate limits); (d) the secrets-redaction filter (CC-6: redact runs BEFORE any content is sent to Jev or Gemini — `classify` does this internally in the production path, and the re-backfill inherits it by calling `classify`). The script **SHALL NOT** bypass the circuit breaker, rate limits, or redaction filter even in backfill mode — backfill is not a license to skip production guardrails. The script does NOT call `Jev.noul`, `Jev.choice`, `Gemini.extract`, or `Buffer.add`/`Buffer.getContext` directly — only `classify(input)` (SC-1).

9. **WHEN** the re-ingest step writes a new MEMORY/ENTITY node via `classify(input)` (the pipeline owns the store per SC-1 — it persists internally via `SurrealHypergraphBackend.store`, step 5; the script does NOT call `persistMemories`/`persistEntities` or `SurrealHypergraphBackend.store` directly), the node **SHALL** carry `source_path: "llm"` (provenance per SC-1) when the LLM path fired, or `source_path: "tool"` when the gate skipped and the regex fallback fired (the production behavior). The script **SHALL** assert that re-ingested MEMORY nodes have `memory_type` set to one of the 7 SC-4 types (`preference`, `correction`, `decision`, `constraint`, `pattern`, `context`, `none` — nodes with `memory_type = "none"` **SHALL NOT** be stored per SC-4; `classify` filters them before persistence). The script **SHALL** count persisted nodes by `memory_type` for the marker (req 11) so the user can see the quality distribution (e.g. 200 preference, 50 correction, 30 decision, 20 constraint, 100 pattern, 80 context).

10. **WHEN** the re-ingest step processes a turn, the script **SHALL** clear the SDD-03 circular buffer at the start of each session (session isolation — the buffer is session-scoped per SC-3). The pipeline (`classify`) owns the buffer per SC-1: it reads prior context via `Buffer.getContext(input.sessionID)` for the gate (step 1) and adds the current turn via `Buffer.add` after classify/store (step 6). The script **SHALL** NOT call `Buffer.add`/`Buffer.getContext` directly — only `classify(input)` touches the buffer per turn. The gate (Jev Noul) **SHALL** receive the buffer context + the current turn as `state` per SC-5. The script **SHALL** NOT carry buffer state across sessions (a session's buffer is independent — the gate decision for session B turn 1 is not influenced by session A's last turns).

### Idempotent markers

11. **WHEN** the re-backfill completes successfully (all sessions processed, no abort), the script **SHALL** write a marker at `~/.local/share/foxybear/rebackfill-phase-n-<dbname>.json` (where `<dbname>` is the basename of the current SQLite DB with `.db` stripped) via `Bun.write` with `{ ran: true, completed_at, db, sessions_processed, sessions_skipped, sessions_errored, nodes_deleted: { ENTITY, MEMORY, PROCEDURE }, nodes_emitted: { ENTITY, MEMORY, PROCEDURE }, hyperedges_deleted, hyperedges_emitted, memories_classified: { preference, correction, decision, constraint, pattern, context }, by_project, duration_ms, snapshot_path, classifier_version, circuit_breaker_fires, fallback_invocations, cost_usd }`. The `classifier_version` **SHALL** be the git SHA of `src/memory/classify/pipeline.ts` (SC-1 authoritative path) (or a version tag from `memory.extraction.layer1`/`layer2` config if `classify` exposes one). The `cost_usd` **SHALL** be the sum of Jev + Gemini call costs (CC-8 cost logging — `classify` already logs per-call cost; the re-backfill aggregates). A subsequent re-backfill run **SHALL** detect the marker and exit 0 with a summary line per the existing pattern at `backfill-hypergraph.ts:90-100` (the existing Phase M marker at `backfill-hypergraph-<base>.json` is preserved — the Phase N marker is a separate file, so a user who ran the Phase M backfill won't auto-re-run Phase N unless they delete the Phase N marker).

12. **WHEN** the re-backfill is invoked with `--force`, the script **SHALL** re-snapshot and re-run regardless of the marker (the existing marker is overwritten on completion). **WHEN** invoked with `--dry-run`, the script **SHALL** run pre-flight + count stub nodes (per type, via `SELECT count(), node_type FROM node WHERE node_type IN ["ENTITY", "MEMORY", "PROCEDURE"] GROUP BY node_type;`) + estimate the cost (sessions × ~$0.0006/turn per master §Cost, with the actual turn count if computable cheaply, else the 50-turn average) WITHOUT any delete or write, and **SHALL** emit a dry-run summary to stdout with the per-type stub-node counts, the estimated cost, the snapshot path (the snapshot **SHALL** still be written in dry-run mode so the user can inspect the pre-state), and the classifier version. **WHEN** invoked with `--legacy`, the script **SHALL** run the original Phase M backfill behavior (emit all 224k nodes via `TraceIngestor.ingest` + the stub extractors, no delete, no `classify`) — the Phase M behavior is preserved behind this flag for users who want to re-run the Phase M backfill on a fresh DB.

### Progress logging

13. **WHEN** the re-backfill is processing sessions, it **SHALL** log progress every 25 sessions (configurable via `--progress-every=N`, default 25) as a single JSON line to stdout: `{ at, sessions_processed, sessions_skipped, sessions_errored, total_sessions, nodes_deleted, nodes_emitted, memories_classified, elapsed_ms, estimated_remaining_ms, circuit_breaker_fires, fallback_invocations, cost_usd_so_far }`. The `estimated_remaining_ms` **SHALL** be a linear extrapolation: `(total_sessions - sessions_processed) × (elapsed_ms / sessions_processed)` (or `null` if `sessions_processed === 0`). The progress line **SHALL** be a single-line JSON (no pretty-printing) so the user can `tail -f | jq` the progress. The existing `if (processed % 10 === 0) console.log(...)` at `backfill-hypergraph.ts:240-242` is REPLACED by this JSON-line progress log (the interval moves from 10 to 25, the format moves from human-readable to JSON, the fields expand to include the Phase N metrics).

### Resume capability

14. **WHEN** the re-backfill is interrupted (Ctrl-C, SIGTERM, crash, power loss), a subsequent run **SHALL** resume from the last completed session: the script **SHALL** write a resume checkpoint at `~/.local/share/foxybear/rebackfill-phase-n-<dbname>-checkpoint.json` every `--checkpoint-every=N` sessions (default 10) via `Bun.write` with `{ last_session_id, last_session_index, last_session_processed_at, snapshot_path, classifier_version, nodes_deleted_so_far, nodes_emitted_so_far, memories_classified_so_far }`. On restart, the script **SHALL** detect the checkpoint, skip already-processed sessions (by `time_created` order — the checkpoint records the last session ID + index, and the script resumes at `index + 1`), and continue. The checkpoint **SHALL** be written AFTER the session's nodes are committed to SurrealDB (not before), so a crash mid-session resumes at the current session, not the next. The delete step (req 3) **SHALL NOT** re-run on resume — the stub nodes are already deleted; the resume resumes the re-ingest loop only. The `REBACKFILL_DELETE` event (req 5) and the snapshot (req 2) are NOT re-emitted on resume.

15. **WHEN** the resume checkpoint is corrupt or unreadable (JSON parse error, missing required fields, `classifier_version` mismatch indicating the pipeline changed mid-run), the script **SHALL** fall back to a full re-run (delete checkpoint, re-snapshot, re-delete stubs, re-ingest from session 0) and **SHALL** log the corruption at `warn` level with the specific failure mode. **WHEN** the `--fresh` flag is passed, the script **SHALL** delete the checkpoint and the marker (but NOT the snapshot — the user might want to restore from a prior snapshot) and start over. The `--fresh` flag **SHALL** re-snapshot before re-deleting (the snapshot is always taken before any delete, even on a fresh run, so the restore point is current).

### New code (new functions in backfill-hypergraph.ts, new test file)

- **`preflight()` function** — runs the four pre-flight checks (req 1). Returns `{ ok: boolean, failing?: string, snapshot_path?: string, fixture_session_id?: string, fixture_node_counts?: { ACTION: number, ERROR: number, MESSAGE: number } }`. Exits non-zero on failure. Calls `TraceIngestor.ingest` against a throwaway `SurrealHypergraphBackend` instance (not the global one) for the determinism check.
- **`snapshot()` function** — exports the `node` and `hyperedge` tables to a JSON file (req 2) via `graph.run("SELECT * FROM node;")` + `graph.run("SELECT * FROM hyperedge;")` + `Bun.write`. Returns the snapshot path. Asserts the snapshot is non-empty + valid JSON + has the required `metadata` fields.
- **`purge()` function** — the bulk delete (req 3, 4). Runs `DELETE FROM node WHERE node_type IN ["ENTITY", "MEMORY", "PROCEDURE"];` then `DELETE FROM hyperedge_members WHERE node_id NOT IN (SELECT node_id FROM node);` then `DELETE FROM hyperedge WHERE id NOT IN (SELECT hyperedge_id FROM hyperedge_members);`. Appends the `REBACKFILL_DELETE` event. Returns per-type deleted counts + deleted hyperedge count + deleted member count.
- **`verify()` function** — the post-purge assertion (req 6). Queries `SELECT count(), node_type FROM node WHERE node_type IN ["ACTION", "ERROR", "MESSAGE"] GROUP BY node_type;` and compares to the snapshot. Exits non-zero on mismatch (fires abort A_N via `m0-abort.ts`).
- **`reingest()` function** — the main re-ingest loop (req 7-10). Iterates sessions ordered by `time_created` ascending, groups into turns, clears the circular buffer at session start, constructs `ClassifyInput` per turn (`{ sessionID, text, project_id, persona }` per SC-1), invokes `classify(input)` (the pipeline handles gate/extract/classify/store/buffer-update internally per SC-1), logs progress (req 13), writes checkpoints (req 14). The script does NOT call `persistMemories`/`persistEntities`, `SurrealHypergraphBackend.store`, or `Buffer.add`/`Buffer.getContext` directly. Returns the aggregate counts for the marker.
- **`resume()` function** — the resume logic (req 14, 15). Reads the checkpoint via `Bun.file(checkpointPath).json()`, returns `{ last_session_index, snapshot_path, classifier_version, ... }` or `null` for a fresh start. Handles corrupt checkpoints (JSON parse error → fall back to fresh, log at `warn`).
- **`RebackfillMarker` interface** — the Phase N marker (req 11). Sibling to the existing `Marker` interface (not an extension — the fields differ enough).
- **`Checkpoint` interface** — the resume checkpoint (req 14).
- **`test/fbh-phase-n/sdd-06.test.ts`** — the acceptance tests for reqs 1-15. New directory `test/fbh-phase-n/` (created lazily — does not exist yet).

### What is explicitly NOT built

- **Re-ingest of deterministic nodes** — the 85k ACTION/ERROR/MESSAGE nodes are PRESERVED (CC-1), not re-ingested. `TraceIngestor.ingest` is called only in the pre-flight determinism check (req 1a) against ONE fixture session against a throwaway backend, not in the main re-ingest loop.
- **Soft-delete of stub nodes** — the 139k stub nodes are HARD-deleted. Soft-delete would leave 139k DELETED records bloating the table and future queries. The `REBACKFILL_DELETE` event (req 5) is the audit trail.
- **Parallel re-backfill-only classifier path** — the re-backfill uses the production `classify` pipeline (CC-2). No `backfill-only-classify` function. The script calls the same function SDD-05 wires into the post-turn hook.
- **Direct persistence calls from the script** — the script does NOT call `persistMemories` / `persistEntities` or `SurrealHypergraphBackend.store` directly. The pipeline owns the store per SC-1 (`classify(input)` persists internally, step 5). The persist helpers are internal to the pipeline.
- **New node/hyperedge types** — the schema is fixed by SDD-03.
- **`deleteNodesByType` method on `SurrealHypergraphBackend`** — the bulk delete is a raw SurrealQL statement via `graph.run`. Adding a one-line wrapper method is out of scope for SDD-06.
- **Live LLM calls in tests** — the acceptance tests use a fixture session + a real SurrealDB backend (or the test fake backend). `classify` is invoked with `external_opt_in = false` in tests (regex fallback), so tests don't make real Jev/Gemini calls. The pre-flight classifier availability check (req 1d) is the only test that makes a real call, and it's gated on `external_opt_in = true` in the test config (skipped in CI unless the test config explicitly opts in).
- **EVIDENCE hyperedge gap fix** — the existing backfill does not emit EVIDENCE hyperedges for the LLM-extracted MEMORY nodes (a pre-existing Phase M gap — `TraceIngestor.ingest` emits EVIDENCE for MEMORY nodes it creates, but the MEMORY nodes come from `MemoryExtractor.extract` which runs AFTER `TraceIngestor.ingest` returns). SDD-06 does NOT fix this gap — `classify` (via SDD-05 wire-up) handles EVIDENCE in the production path, and the re-backfill inherits whatever EVIDENCE behavior the production path has. Fixing the EVIDENCE gap is a Phase M / SDD-05 concern.
