# Independent Adversarial Audit — SDD-02..05 v2 Amendments (Final Review)

**Auditor:** Independent adversarial auditor (not the spec author)  
**Date:** 2026-08-07  
**Scope:** Final re-review of `260806_voice-tts_sdd-v2-02-05-amendments.md` and dependency `260806_voice-tts_sdd-v2-01-system-commands.md`, against the 12 blocking issues reported in the prior audit.

## Audit Method

Read the current revision of the amendment spec and SDD-01 v2, then verified each of the 12 previously reported blocking issues for:

1. Explicit resolution in the current text.
2. Internal consistency across the v2 specs.
3. Independent testability in the `VERIFY` criteria.
4. Absence of new contradictions introduced by the revision.

---

## Blocking Issues Review

### 1. `VoiceEngine.stop` not session-scoped

**Status:** RESOLVED

**Evidence:**
- `VoiceEngine` interface declares `stop: (sessionID: string, urgency: "immediate" | "flush") => Effect.Effect<void>` (amendment §HOW/SDD-03 v2, SDD-01 v2 §HOW/`VoiceEngine` contract).
- Barge-in protocol calls `engine.stop(sessionID, "immediate")` (SDD-01 v2 §WHAT.8, §HOW/Barge-in).

**Analysis:** `stop` is now unambiguously per-session. Multi-session isolation is preserved.

---

### 2. `getStatus` / `getCapabilities` not session-scoped

**Status:** RESOLVED

**Evidence:**
- `VoiceEngine` interface declares `getStatus: (sessionID: string) => EngineStatus` and `getCapabilities: (sessionID: string) => EngineCapabilities` (amendment §HOW/SDD-03 v2; SDD-01 v2 §HOW/`VoiceEngine` contract).
- `VoiceService` exposes `getEngineStatus(sessionID)` (SDD-01 v2 §HOW/`Voice.Service` interface).

**Analysis:** Both query methods are session-scoped and aligned with the rest of the contract.

---

### 3. Optional hooks / capability guard undefined

**Status:** RESOLVED

**Evidence:**
- SDD-01 v2 §HOW/`VoiceEngine` contract: "`Voice.Service` only invokes methods and reads capability flags that are defined in `EngineCapabilities`. There are no optional hooks in the base `VoiceEngine` contract."
- `EngineCapabilities` contains only `streaming`, `bargeInSupport`, `flush`, and `outputFormat` — no optional-method flags.
- `VERIFY V7` now tests: "`Voice.Service` only calls methods and reads capability flags defined in `EngineCapabilities`; no optional hooks are probed" (amendment §VERIFY).

**Analysis:** The prior revision referenced an undefined `onBargeIn` optional hook in `VERIFY V7`. The current revision removes optional hooks from the base contract entirely and redefines `VERIFY V7` accordingly. The capability guard is now well-defined: `Voice.Service` reads only advertised `EngineCapabilities` fields and calls only methods on the required interface.

---

### 4. `synthesize` `utteranceId` optional, but events keyed by it

**Status:** RESOLVED

**Evidence:**
- `synthesize` signature: `options: { utteranceId: string }` (amendment §HOW/SDD-03 v2; SDD-01 v2 §HOW/`VoiceEngine` contract).
- Amendment §HOW/SDD-03 v2: "`options.utteranceId` is required."
- Playback lifecycle events carry `utteranceId`.

**Analysis:** The caller must supply `utteranceId`, eliminating the key-generation ambiguity.

---

### 5. `VoiceEngine.connect` did not accept `VoiceConfig`

**Status:** RESOLVED

**Evidence:**
- Amendment §HOW/SDD-03 v2: "The module receives `VoiceConfig` from the instance layer at construction time."
- `connect` signature is `connect: (sessionID: string) => Effect.Effect<void>` (no config parameter).
- SDD-01 v2 §HOW/`VoiceEngine` contract: "The engine is constructed by the instance layer and handed to `Voice.Service`."

**Analysis:** Config injection at construction is explicit and consistent; `connect` is session-only.

---

### 6. Sink `stop(sessionID)` exposed to `Voice.Service`

**Status:** RESOLVED

**Evidence:**
- Amendment §HOW/SDD-04 v2: "The sink is owned by the TTS engine module (SDD-03 v2) and receives `play(sessionID, audioStream)` and `stop(sessionID)` calls from the engine, which are triggered by `Voice.Service`."
- `Voice.Service` calls `engine.stop(sessionID, urgency)`; the engine internally forwards to the sink.

**Analysis:** The sink's `stop` is no longer part of the `VoiceEngine` contract exposed to `Voice.Service`. Abstraction boundary is restored.

---

### 7. Tap integration path unresolved

**Status:** RESOLVED

**Evidence:**
- Amendment §HOW/SDD-02 v2: "The tap receives Bus events through the existing plugin `event` hook and forwards text deltas to `Voice.Service.feedText(sessionID, delta)`."
- SDD-01 v2 §HOW/Tap wiring: "SDD-02 v2 calls `Voice.Service.feedText(sessionID, delta)` for each assistant text delta when `mode === "on"`."

**Analysis:** A single, unambiguous integration path is specified: plugin `event` hook → `Voice.Service.feedText`. No competing "OR" paths remain.

---

### 8. Tap stop signal not wired into barge-in

**Status:** RESOLVED

**Evidence:**
- Amendment §HOW/SDD-02 v2: "The tap accepts a `stopTap(sessionID)` signal from `Voice.Service` to terminate the active async iterable on barge-in."
- SDD-01 v2 §HOW/Tap wiring: "On barge-in, `Voice.Service` also signals the tap to terminate its async iterable."

**Analysis:** The barge-in protocol now explicitly terminates the tap's async iterable, preventing stale deltas from leaking past barge-in.

---

### 9. Mandatory observability events not representable

**Status:** RESOLVED

**Evidence:**
- `EngineEvent` union includes `connected`, `disconnected`, `synth_accepted`, `status_changed`, and playback lifecycle events (amendment §HOW/SDD-03 v2; SDD-01 v2 §HOW/`VoiceEngine` contract).
- Amendment §HOW/Mandatory Observability: "The `EngineEvent` union includes `connected`, `disconnected`, and `synth_accepted` to satisfy this."

**Analysis:** Engine-level observability events are representable. Service-level events (command invoked, state transitions, abort, teardown, config-validation failure) are owned by `Voice.Service` and covered by `VoiceStatePart` and Bus events. The split is consistent.

---

### 10. `InMemoryVoiceEngine` circular requirement

**Status:** RESOLVED

**Evidence:**
- Amendment §HOW/Testability: "SDD-03 v2 SHALL specify an `InMemoryVoiceEngine` in the shared package implementing the full required `VoiceEngine` surface, emitting observable state events, and injectable via Effect context."
- `VERIFY V10` / SDD-01 v2 `VERIFY V15` require contract tests against the required surface.

**Analysis:** The test double is required to implement only the required `VoiceEngine` surface, not undefined optional hooks. The circular dependency on optional-hook definitions is removed.

---

### 11. Output muting effect on tap unspecified

**Status:** RESOLVED

**Evidence:**
- Amendment §HOW/SDD-02 v2/Added v2 surfaces: "When `mode === "on"` and `output === "muted"`, the tap continues forwarding text; muting suppresses playback downstream, not synthesis."
- `VoiceState` has orthogonal `mode` and `output` dimensions (SDD-01 v2 §HOW/Command semantics).

**Analysis:** The behavior under `mode === "on"` / `output === "muted"` is now explicit: the tap keeps forwarding text; muting acts downstream on playback, not on synthesis or tap forwarding. `/mute` semantics are complete.

---

### 12. `VERIFY V6` mixed engine and service behavior

**Status:** RESOLVED

**Evidence:**
- Amendment §VERIFY: "V6 — Flush fallback (engine-only). Setup: engine with `capabilities().flush === false`. Action: call `stop(sessionID, "flush")`. Expected: engine treats it as `stop(sessionID, "immediate")`."

**Analysis:** The verification criterion is now purely engine-level. The service-side degradation recording is tested separately via state-transition and `VoiceStatePart` criteria.

---

## New Issues Introduced by the Revision

No new material contradictions were identified. The two previously blocking gaps — optional hooks and muted-output tap behavior — are now closed.

## Non-Blocking Observations

- **"Full transition matrix" in contract tests.** `VERIFY V10` still calls for a "full transition matrix" without enumerating every state pair. This is acceptable at the spec level but should be expanded in the implementation test plan.
- **Expressivity packaging.** The amendment remains neutral on whether expressivity hooks live in the engine module or a separate plugin. This is a packaging decision, not a spec contradiction.
- **Abort observability completeness.** The mandatory observability list includes "abort requested/completed/failed" and "teardown"; these are appropriately `Voice.Service`-owned and surfaced via `VoiceStatePart`/Bus events. A cross-reference in the observability section would improve readability but is not blocking.

---

## VERDICT: PASS

All 12 previously reported blocking issues are resolved in the current revision. The `VoiceEngine` contract is session-scoped and free of undefined optional hooks; the tap integration and barge-in wiring are explicit; sink ownership and observability events are internally consistent; and `/mute` semantics are complete. The spec is ready for implementation subject to normal implementation-level detailing.

VERDICT: PASS
