M-6 is the verification phase. It ports an AgentMemBench-style benchmark harness to fbh, runs A/B tests across the memory system's two axes (relational reasoning via hypergraph, long-range recall via SQLite KV), tunes the thresholds introduced in sdd-06 (decay + semantic-shift, M-3), sdd-07 (packing budget, M-4), and sdd-09 (conflict cosine, M-5 — pre-calibration, since M-5 is deferred to post-M-6), measures the contradiction rate in the corpus (the evidence sdd-09 consumes to decide whether to activate), and runs a live smoke test against the real `fbh` binary on a real LLM provider. No spike — M-6 IS the verification. Per council re-sequencing, M-6 runs BEFORE M-5 (sdd-09). If the contradiction rate is below the pre-registered threshold (req 16), abort A8 fires and M-5 is deferred indefinitely.

## Background

Research (`docs/research/260921_fbh-phase-m_research.md` §8 AgentMemBench) found that graph methods (GEM) collapse at long-range recall (Recall@5 ≤ 0.005 on LoCoMo, vs EKV's 0.573). The hypergraph in Phase M is for **relational/structured reasoning** (who did what with what tool, after what error, producing what evidence), not bulk recall. SQLite KV (`memory_topics` / `node` MEMORY type) remains the long-range workhorse. M-6 MUST verify both axes independently: relational queries where the hypergraph should win, AND long-range recall where KV should win (verifying the hypergraph does not regress it). The benchmark is not "does the hypergraph beat KV on everything" — it is "does the hypergraph add relational value without regressing long-range recall."

M-6 inherits CC-4 (green suite), CC-5 (real verification, no mocks of our code), CC-9 (single-word names), CC-11 (pre-registered instruments), SC-10 (verification commands), and SC-11 (abort criteria A7, A8) from the master. Tests run from `packages/fbh` (never repo root — the `do-not-run-tests-from-root` guard).

## WHAT

### Benchmark harness

1. **WHEN** M-6 begins, the system **SHALL** provide a benchmark harness at `packages/fbh/src/memory/bench/` that drives the memory system through the daemon HTTP API (`/memory/write`, `/memory/query`, `/memory/forget`, `/memory/list`, `/memory/metrics`, `/memory/prunable` at `src/daemon/routes.ts:57-110`) and computes the seven AgentMemBench metrics: Recall@k for k=1,5,10, MRR, nDCG@k, Answer F1, LLM-judge Faithfulness, Memory Footprint (tokens), and Latency (ms).

2. **WHEN** the harness runs, it **SHALL** use a real LLM provider for generation and judging (no request mocking, per CC-5), with deterministic decoding (greedy, temperature=0) so a re-run against the same fixture produces the same aggregate metric values within ±1% tolerance. Extraction LLM calls (Qwen2.5-7B-Instruct on DeepInfra, per sdd-05) **SHALL** be real, with a low `MAX_PER_SOURCE` cap to bound cost. The harness **SHALL** record the provider ID, model ID, git SHA, and fixture IDs in every results file for reproducibility.

3. **WHEN** the harness runs, it **SHALL** emit a JSON results file at `~/.local/share/foxybear/bench/<timestamp>-<name>.json` containing per-query metrics, aggregate metrics, the fixture ID, the harness config (provider, model, budget, threshold values), and the git SHA. A re-run with the same config + fixture **SHALL** reproduce the aggregate metrics within ±1% (reproducibility).

### A/B: with vs without memory injection

4. **WHEN** the harness runs the injection A/B, it **SHALL** run the same query fixture twice — once with `@foxybear/ContextPacker.pack` wired into the prompt (per sdd-07) and once with the packer disabled (memory_topics / `node` MEMORY type never read for injection) — against the same real provider with the same deterministic decoding. The harness **SHALL** compute Answer F1 and LLM-judge Faithfulness for both arms, **SHALL** record which arm scored higher per query and in aggregate, and **SHALL** report a Wilcoxon signed-rank p-value alongside the delta. The injection A/B **SHALL** use at least 30 paired queries. If the `with_memory` arm does not outscore the `without_memory` arm on aggregate Faithfulness, the harness **SHALL** flag `INJECTION_NO_GAIN` and the spec **SHALL NOT** pass.

### A/B: with vs without hypergraph (relational)

5. **WHEN** the harness runs the relational A/B, it **SHALL** run a fixture of relational queries of the form "what did agent X do with tool Y after error Z?" (where the answer requires joining ActionNode + ErrorNode + AgentNode + ToolNode via hyperedges from sdd-03). The harness **SHALL** run the same queries two ways: (a) KV-only retrieval (cosine over `memory_topics` / `node` MEMORY type), (b) hypergraph retrieval (sdd-03 `@foxybear/Hypergraph.query` with hyperedge expansion). For each arm the harness **SHALL** compute Recall@k, MRR, nDCG@k, and Answer F1. The hypergraph arm **SHALL** outperform the KV arm on Recall@5 for relational queries by at least 0.10 (the value proposition the hypergraph exists to deliver). If the hypergraph does NOT outperform KV on relational queries, the harness **SHALL** flag `RELATIONAL_REGRESSION` and the spec **SHALL NOT** pass.

### Long-range recall (KV axis, regression guard)

6. **WHEN** the harness runs the long-range recall test, it **SHALL** run a fixture of long-range queries (answers located >50 turns back in the session, or in `memory_topics` rows older than 7 days) using KV retrieval (`memory_topics` / `node` MEMORY type) and **SHALL** compute Recall@5. The harness **SHALL** also run the same long-range fixture through the hypergraph retrieval path and compute Recall@5. The hypergraph Recall@5 on long-range queries **SHALL** not be more than 0.05 below the KV Recall@5 (regression guard). If the hypergraph regresses long-range recall by more than 0.05, the harness **SHALL** flag `LONG_RANGE_REGRESSION` and the spec **SHALL NOT** pass. This enforces the AgentMemBench caveat: graph is for relational reasoning, not bulk recall.

### Threshold tuning

7. **WHEN** M-6 tunes the sdd-06 decay rates, it **SHALL** sweep `memory.decay.active_rate`, `memory.decay.deprecated_rate`, `memory.decay.archived_rate`, and `memory.decay.rehearsal_boost` (per SC-6) across a parameter grid, run the benchmark harness at each grid point, and **SHALL** select the values that maximize Answer F1 on the relational fixture without regressing long-range Recall@5 by more than 0.05. The selected values **SHALL** be written to `~/.local/share/foxybear/bench/<timestamp>-decay-tune.json` alongside the grid and per-point metrics.

8. **WHEN** M-6 tunes the sdd-09 conflict detection cosine threshold (pre-calibration — M-5 is deferred to post-M-6, so this produces a recommended value for sdd-09 to consume if it activates), it **SHALL** sweep `memory.conflict.cosine_threshold` across `[0.20, 0.25, 0.30, 0.35, 0.40]`, run a contradiction fixture (100 pairs: 50 real contradictions, 50 not), and **SHALL** select the threshold that minimizes false-positive rate while keeping true-positive rate ≥ 0.60. The selected threshold **SHALL** be written to `~/.local/share/foxybear/bench/<timestamp>-conflict-tune.json`. The selected threshold **SHALL** satisfy the sdd-09 spike pass criterion (FP < 10%) when sdd-09 activates. If sdd-09 is deferred (abort A8, per req 16), the selected threshold is recorded as a recommended value for future use.

9. **WHEN** M-6 tunes the sdd-07 packing budget, it **SHALL** sweep `memory.packing.budget_tokens` across `[512, 1024, 2048, 4096]`, run the benchmark harness at each value, and **SHALL** select the budget that maximizes Answer F1 minus a footprint penalty (Footprint tokens / 10_000). The selected budget **SHALL** be written to `~/.local/share/foxybear/bench/<timestamp>-budget-tune.json`. The Footprint metric **SHALL** be reported alongside Answer F1 to make the trade-off explicit.

10. **WHEN** M-6 tunes the sdd-06 semantic-shift graduation trigger, it **SHALL** sweep the semantic-shift embedding-delta threshold across `[0.10, 0.15, 0.20, 0.25, 0.30]`, run a graduation fixture (instance-scoped memories that should / should not graduate), and **SHALL** select the threshold that maximizes graduation precision (correctly-graduated / total-graduated) subject to a recall floor (correctly-graduated / should-graduate ≥ 0.80). The selected threshold **SHALL** be written to `~/.local/share/foxybear/bench/<timestamp>-shift-tune.json`.

## HOW

- **Harness:** new `packages/fbh/src/memory/bench/` directory. Entry point `bench.ts` exposes `bench(name, fixture, opts)` that runs the seven metrics against the daemon HTTP API. Fixtures live in `packages/fbh/test/fbh-phase-m/fixtures/` as JSON arrays of `{ query, expected_answer, expected_node_ids, turn_index }`. The harness boots the daemon via `bun link` + `fbh serve --background` (SC-10), waits on `/health` (the `describeRoute` at `src/daemon/routes.ts:116`), then drives sessions through `HeadlessSession.run` at `src/daemon/headless.ts:42` (wired by `Runner.wire` at `src/daemon/runner.ts:29`, invoked from the `http` subsystem init at `src/cli/cmd/serve.ts:155`).
- **Metrics:** Recall@k, MRR, nDCG@k computed from `expected_node_ids` vs the retrieved `node_ids` returned by `/memory/query` (`src/daemon/routes.ts:67`). Answer F1 computed by token-overlap between the LLM answer and `expected_answer`. LLM-judge Faithfulness via a second LLM call (same provider, greedy decoding) with the prompt "Is this answer supported by the retrieved context? Reply YES/NO/PARTIAL." Footprint = tokens of injected context (the `## Relevant Memories` block from `AutoRecall.formatForInjection` at `src/memory/recall.ts:279`, token-counted). Latency = wall-clock from query to response.
- **Relational fixture:** 30+ queries of the form "what did agent X do with tool Y after error Z?" generated from a synthetic session trace with known ActionNode / ErrorNode / AgentNode / ToolNode IDs (from sdd-03). The fixture author hand-labels `expected_node_ids` (the ActionNode for the action after the error) and `expected_answer` text.
- **Long-range fixture:** 30+ queries whose answers live in `memory_topics` rows older than 7 days (or >50 turns back), hand-labeled. The harness loads these into the SQLite KV store via `/memory/write` (`src/daemon/routes.ts:59`) before the test, with `valid_from` set back-dated.
- **A/B runner:** `ab(name, fixture, arms)` runs the same fixture across `arms` (a map like `{ with, without }` or `{ kv, hypergraph }`) and emits a paired comparison. Statistical significance via Wilcoxon signed-rank (inline implementation; no new heavy dependency).
- **Tuning:** `tune(name, param, grid, fixture, score)` sweeps a config value, runs `bench` at each point, scores, picks the best. The config change is applied by editing `~/.config/foxybear/fbh.json` between runs (CC-6: config-driven, not hardcoded). The selected values are written to a tune JSON for review.
- **Contradiction-rate mode:** `contradiction(corpus)` ingests the corpus through the sdd-05 auto-capture pipeline, writes each new memory via `/memory/write`, then for each new memory retrieves candidate existing memories via cosine similarity (threshold 0.30) and runs an LLM-judge contradiction check. Results written to `~/.local/share/foxybear/bench/<timestamp>-contradiction.json` with the rate, severity distribution, and per-project breakdown. The A8 decision (defer or activate M-5) is recorded in the JSON and the results doc.
- **Smoke:** `smoke()` boots the daemon (`fbh serve --background`), waits on `/health`, runs a 4-turn script (intro, tool call, error, contradiction) through `HeadlessSession.run`, then queries the `node`, `hyperedge`, and `event` tables directly via the SurrealDB connection (or a `/debug/state` route added in M-6 if direct Surreal access from the test is awkward) to assert WHAT 12a–12d. Assertion 12d is SKIPPED if sdd-09 (M-5) is deferred (abort A8). The smoke checklist is a markdown file written by the test.
- **Results doc:** generated from the harness output JSONs by a `report.ts` script that assembles the markdown. Doc lives at `docs/research/260922_fbh-phase-m_benchmark.md` (sibling of the phase-m research doc at the FoxyBearOffice root — the agent-coordination hub where Phase M research lives, not the per-project `development/foxybear/docs/research/`).
- **Verification commands (SC-10, run from `packages/fbh`):**
  - Typecheck: `bun run typecheck` → `tsgo --noEmit` (`packages/fbh/package.json:10`)
  - Test: `bun test --timeout 30000` (`packages/fbh/package.json:11`)

  - Live smoke: `fbh serve --background` → `/health` → `HeadlessSession.run`
- **What is explicitly NOT built:** no new memory services (those live in sdd-03 through sdd-07, with sdd-09 deferred to post-M-6); no mocks of the implementation under test (CC-5) — the harness hits the real daemon HTTP API and the real LLM provider; no new node/hyperedge types (the schema is fixed by sdd-03); no new tables (sdd-03 owns the schema).
- **Reuse map:**
  - `src/daemon/routes.ts:57` `memoryRoutes()` — benchmark API surface (`/memory/write`, `/memory/query`, `/memory/forget`, `/memory/list` GET+POST, `/memory/metrics`, `/memory/prunable`)
