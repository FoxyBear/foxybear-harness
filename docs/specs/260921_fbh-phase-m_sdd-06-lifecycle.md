# SDD-06: Phase M-3 — Lifecycle Engine

**Date:** 2026-09-21 (revised 2026-09-22 per council deliberation)
**Project:** FoxyBear Harness Phase M (`development/foxybear`)
**Status:** Draft (pending independent re-audit + human gate)
**Master:** `260921_fbh-phase-m_sdd-00-master.md`
**Research:** `docs/research/260921_fbh-phase-m_research.md` (§Phase M-3, §Papers studied — Prism, GAM)
**Depends on:** `sdd-02` (M-0 wire-up: real `recentSessionIds`, scheduler enabled, SurrealDB path fixed), `sdd-03` (M-1 hypergraph schema: `node`/`hyperedge`/`event` tables, bi-temporal fields, `LifecycleStatus` enum, `is_live` filter), `sdd-04` (pre-registered retrieval-quality probe: must PASS — gates sdd-05/sdd-06/sdd-07 per master SC-12), `sdd-05` (M-2 auto-capture: access events on `MemoryNode` via `TraceIngestor` + `Consolidation.extractTurn`; provides `usage_count` increments and the shadow-metric embedding-delta computation).

Implements Phase M-3: simple exponential + rehearsal decay as DEFAULT (hourly heartbeat), `access_count >= 2` graduation default with semantic-shift as shadow metric and force-promote at 5, composite value scoring, `LifecycleStatus` transitions, re-enable `Consolidation.prune` + existing graduation, add `memory-decay` and `memory-gc` scheduler tasks. Prism replicator-decay is experimental behind `memory.decay_model=prism` config flag (ESMS convergence proof unverified). The coupled-loop simulation (CC-15) gates the decay engine: it tests the FULL system interaction (decay + graduation + conflict interaction), not just the decay math. After two tuning rounds, oscillation > 2 states or no convergence triggers abort A5 (freeze lifecycle at TTL + near-dup; ship without the decay engine).

## Background

Research found the existing lifecycle scaffold is built but dormant: TTL prune (`consolidation.ts:445`), near-dup merge, 200-entry index cap, graph graduation (`graph/graduation.ts:19`), and a binary 0.5× stale penalty (`memory.ts:458`). All are dormant because the scheduler is disabled (`scheduler.ts:55`) and the `memory-ttl-pruning` task inlines `Memory.getPrunable` + `Memory.forget` instead of calling `Consolidation.prune` (so `prune` has zero call sites — CC-2 violation). The `memory-graduation` task exists at `scheduler.ts:411` but uses `_config.workforce_sync` (every 6 hours) and a hardcoded `project_id: "global"`, not the SC-6 `tasks.graduation.interval: "daily"` config. No Ebbinghaus-style decay exists. No four-stage lifecycle. Graduation triggers on `access_count >= 2` (a parameter-free heuristic — the council confirmed this is the right default per OQ5; semantic-shift is shadow-only, with force-promote at 5 to bound the gating bug where a memory needed 10+ accesses).

This spec wires the dormant prune + graduation, replaces the binary stale penalty with simple exponential + rehearsal decay (the DEFAULT decay model per council Decision 3; Prism replicator-decay is experimental behind the `memory.decay_model=prism` config flag, ESMS convergence proof unverified), preserves `access_count >= 2` as the graduation trigger (per council OQ5 resolution) with semantic-shift as a shadow metric (training data for a future threshold, zero production risk) and force-promote at 5 accesses, adds the `ARCHIVED → DELETED` GC path, and exposes it all through the `@foxybear/MemoryLifecycle` Effect service (SC-5). The coupled-loop simulation (CC-15) gates the decay engine: it tests the FULL system interaction (decay + graduation + conflict interaction), not just the decay math. After two tuning rounds, oscillation > 2 states or no convergence triggers abort A5 (freeze lifecycle at TTL + near-dup; ship without the decay engine).

## WHAT

### Spike — coupled-loop simulation (CC-15, SC-7, CC-3)

1. **WHEN** SDD-06 enters the `tests` stage, the spec's acceptance tests **SHALL** include a coupled-loop simulation spike test (`test/fbh-phase-m/sdd-06-spike.test.ts`) that runs the FULL lifecycle system interaction — decay (simple exponential + rehearsal default per req 4) + graduation (`usage_count >= 2` default per req 12 + force-promote at 5 per req 14) + conflict interaction (soft-deletes via `invalidated_by` + `INVALIDATE` event per req 6, with synthetic contradictions injected at known tick boundaries) — against 1000 synthetic memories across 1000 hourly iterations, with mixed access patterns (no access, single access, periodic access, continuous access), periodic graduation candidate arrival (accesses that push memories to `usage_count = 2` or `usage_count = 5`), and synthetic contradictions injected at ticks 100, 300, 500, 700, 900. The sim **SHALL** assert the system reaches a stable steady state: (a) confidence stays bounded in `[0.0, 1.0]` for all 1000 iterations across all memories (no divergence, no clamping violations), (b) memories with `usage_count >= 1` stabilize above zero (no collapse to zero), (c) graduation promotion decisions converge (oscillation in the set of promoted memory IDs ≤ 2 distinct steady-state sets across the last 200 ticks), (d) no memory cycles `ACTIVE → DEPRECATED → ACTIVE` more than 2 times in 1000 ticks, (e) soft-deleted memories stay deleted (no resurrection — `is_live` remains `false`, `status` stays `DELETED`).

2. **WHEN** the coupled-loop sim (req 1) fails any criterion after the first run, the implementation **SHALL** be tuned (decay rates in `memory.decay.*`, `deprecated_threshold`, `archived_threshold`, `archive_age_days`, `force_promote_access_count`) and the sim **SHALL** be re-run. **WHEN** the sim fails any criterion after a second tuning round (oscillation > 2 distinct steady-state promotion sets OR no convergence of promotion decisions OR confidence divergence outside [0, 1] OR collapse of accessed memories to zero OR `ACTIVE ↔ DEPRECATED` cycling > 2 times per memory OR soft-delete resurrection), the HOW **SHALL** trigger abort A5 per SC-11: freeze lifecycle at TTL + near-dup, ship without the decay engine (the `memory-decay` scheduler task remains registered but becomes a no-op that logs "decay engine disabled (abort A5)" at info level; the `memory-graduation` task falls back to `usage_count >= 2` with no confidence-based transitions; the `memory-gc` task continues to hard-delete `ARCHIVED` records past retention; the `memory.decay_model` config field is locked to `none` and config overrides are ignored with a warning). Tuning changes **SHALL** be recorded in the decision log with the parameter delta and the resulting sim metrics.

3. **WHEN** the coupled-loop sim runs, it **SHALL** use the per-stage decay rates from `memory.decay.active_rate` (0.01), `memory.decay.deprecated_rate` (0.05), `memory.decay.archived_rate` (0.1), and `memory.decay.rehearsal_boost` (0.1) per access for the default simple-exponential model. **WHEN** `memory.decay_model=prism` is set (experimental flag, default is `simple`), the sim **SHALL** additionally run the Prism replicator-decay formula and report its convergence metrics alongside the default's; the Prism run does NOT gate the default — it is observational only, gathering data for a future ESMS-verified promotion decision. The Prism formula **SHALL** be implemented in a separate function (`prism_decay.ts`) that is not imported by the production `decay` function when `decay_model=simple` (default). The sim **SHALL NOT** call the production `decay` function — it is throwaway code that validates the coupled-loop interaction in isolation (CC-3).

### Lifecycle status transitions (SC-3)

4. **WHEN** the `@foxybear/MemoryLifecycle.decay` Effect runs (hourly via the `memory-decay` scheduler task), it **SHALL** load every `node` record with `status` in `{ACTIVE, DEPRECATED, ARCHIVED}` and `is_live(now) === true` (SC-2), and for each **SHALL** compute `confidence(t+1) = min(1.0, max(0.0, confidence(t) * (1 - rate(status)) + rehearsal_boost * access(t)))` (clamped to [0, 1] per SC-4) where `rate(ACTIVE) = active_rate`, `rate(DEPRECATED) = deprecated_rate`, `rate(ARCHIVED) = archived_rate`, `access(t) = 1` if the node was accessed since the last decay tick (tracked via `last_used` field) and `0` otherwise, and **SHALL** persist the updated `confidence` to the `node` table. This simple exponential + rehearsal formula is the DEFAULT decay model (per council Decision 3); Prism replicator-decay is experimental behind `memory.decay_model=prism` (req 10).

5. **WHEN** `decay` computes a node's new confidence, it **SHALL** evaluate lifecycle transitions in order (matching SC-3's staged model — no direct `ACTIVE → ARCHIVED` transitions): (a) **IF** `confidence < deprecated_threshold` (0.3) **AND** `status === ACTIVE`, transition `status` to `DEPRECATED`; (b) **ELSE IF** `confidence < archived_threshold` (0.1) **AND** `status === DEPRECATED`, transition `status` to `ARCHIVED`; (c) **ELSE IF** `age_days > archive_age_days` (90) **AND** `usage_count < 2` **AND** `status === DEPRECATED`, transition `status` to `ARCHIVED`. The `status` field on the `node` record **SHALL** be updated atomically with the `confidence` update, and an `event` record of type `STATUS_TRANSITION` **SHALL** be appended to the `event` table with the prior and new status in the payload.

6. **WHEN** a node is soft-deleted (via `memory_forget` tool, conflict detection in SDD-09, or any explicit `forget` call), the system **SHALL** set `tx_to = now`, `status = DELETED`, set `invalidated_by` to the ID of the node that caused the invalidation (SC-2 back-pointer field, or `null` if user-initiated without a specific contradicting node), and append an `INVALIDATE` event to the `event` table (SC-9). No hyperedge **SHALL** be created — `INVALIDATES` is not a hyperedge type (SC-3, SC-4). The node record **SHALL** be preserved (no hard-delete). A subsequent `is_live(now)` query **SHALL** return `false` for the deleted node.

7. **WHEN** the `@foxybear/MemoryLifecycle.gc` Effect runs (weekly via the `memory-gc` scheduler task), it **SHALL** select every `node` record with `status === ARCHIVED` and `age_days > retention_days` (365, where `age_days` is measured from `created_at`), and for each **SHALL** append a `GC_DELETED` event to the `event` table (preserving the audit trail per the master Security section) and then hard-delete the `node` record from the `node` table. **SHALL NOT** hard-delete any record with `status !== ARCHIVED`. **SHALL NOT** hard-delete any `ARCHIVED` record with `age_days <= retention_days`.

8. **WHEN** a node is contradicted by a newer memory (detected by SDD-09 `ConflictDetector.check` returning `verdict: "DELETE"` against the node), the system **SHALL** transition the contradicted node per req 6 (soft-delete via `tx_to = now`, `status = DELETED`, `invalidated_by` set to the contradicting node's ID, `INVALIDATE` event appended) and **SHALL** set `contradiction_count += 1` on the contradicting node. No hyperedge **SHALL** be created.

### Decay — simple exponential + rehearsal default, Prism experimental (SC-5, gated by coupled-loop sim)

9. **WHEN** the `memory-decay` scheduler task fires (hourly), it **SHALL** invoke `@foxybear/MemoryLifecycle.decay(now)` and **SHALL** return `{ decayed: number, transitioned: number }` where `decayed` is the count of nodes whose `confidence` changed and `transitioned` is the count of nodes whose `status` changed. The task **SHALL** log both counts at info level. The task **SHALL NOT** run if `memory.scheduler.tasks.decay.interval` is unset or `memory.scheduler.enabled === false`.

10. **WHEN** `decay` runs, it **SHALL** read `active_rate`, `deprecated_rate`, `archived_rate`, `rehearsal_boost`, `deprecated_threshold`, `archived_threshold`, `archive_age_days` from `memory.decay` config (SC-6), and **SHALL** fall back to the SC-6 defaults if any field is missing. **WHEN** `memory.decay_model=simple` (default), `decay` **SHALL** apply the simple exponential + rehearsal formula per req 4. **WHEN** `memory.decay_model=prism` (experimental, ESMS convergence proof unverified), `decay` **SHALL** dispatch to the Prism replicator-decay implementation in `src/memory/lifecycle/prism_decay.ts`. **WHEN** `memory.decay_model=none` (the abort A5 state per req 25), `decay` **SHALL** be a no-op that logs "decay engine disabled" at info level and returns `{ decayed: 0, transitioned: 0 }`. The decay **SHALL** be a single SurrealQL transaction per tick (or a batched transaction) — not a per-node round-trip — to bound latency at 1000-node scale.

11. **WHEN** a node's `last_used` timestamp is more recent than the last decay tick (indicating access since the last tick), `decay` **SHALL** apply the rehearsal term `rehearsal_boost * 1` to that node's confidence update (gating `access(t) = 1`), and **SHALL** reset the access-tracking state after the decay tick so the next tick's `access(t)` reflects only accesses since the prior tick. The `usage_count` field **SHALL** be incremented by the number of accesses since the last tick (not by 1 per tick). These access events are produced by SDD-05's `TraceIngestor` and `Consolidation.extractTurn` (SDD-06 depends on SDD-05 for access events).

### Graduation — `usage_count >= 2` default, semantic-shift shadow, force-promote at 5 (SC-5, OQ5 resolution)

12. **WHEN** the `memory-graduation` scheduler task fires (daily per `memory.scheduler.tasks.graduation.interval`), it **SHALL** invoke `@foxybear/MemoryLifecycle.graduate()` which **SHALL** promote instance-scoped memories with `usage_count >= 2` to the project-scoped graph: for each such memory, extract entities and relations (via the existing `extractEntitiesAndRelations` at `graph/extraction.ts`), upsert them into the project graph via `GraphBackend.upsertEntity` and `GraphBackend.addEdge`, and link the source memory to its extracted entities. The existing `graduateMemories` function at `graph/graduation.ts:19` **SHALL** be called unchanged — the `gte(MemoryTopicsTable.access_count, 2)` filter at `graduation.ts:43` is PRESERVED (this is the parameter-free default per OQ5; no `candidates` parameter is introduced). The `usage_count >= 2` trigger is parameter-free (no embedding-delta threshold to tune); semantic-shift is shadow-only (req 13).

13. **WHEN** a Memory node is accessed (via SDD-05 `TraceIngestor` or `Consolidation.extractTurn`), the system **SHALL** compute the embedding-delta cosine similarity between the access context and the memory's content, and **SHALL** append a `SHADOW_METRIC` event to the `event` table with `{ memory_id, access_context_embedding_delta, timestamp }` in the payload. This is a SHADOW metric — it **SHALL NOT** affect graduation, decay, or scoring decisions. It is training data for a future semantic-shift threshold (the council ruled semantic-shift requires tuning an embedding-delta threshold with no labeled data, so it is shadow-only until labeled data exists). The shadow metric **SHALL** be off by default (`memory.graduation.semantic_shift_shadow = false`); **WHEN** set to `true`, the system logs the metric. Zero production risk: the metric is logged but never read by the lifecycle.

14. **WHEN** a Memory node's `usage_count` reaches 5 (the force-promote threshold, config: `memory.graduation.force_promote_access_count`, default 5), `graduate()` **SHALL** promote it to the project-scoped graph on the next graduation tick REGARDLESS of whether the `usage_count >= 2` filter already covered it. The force-promote is a safety bound against the gating bug where a memory needed 10+ accesses to graduate; **WHEN** `usage_count >= 2` already promoted it, the force-promote is a no-op for that memory. **WHEN** `force_promote_access_count` is set to 0, force-promote **SHALL** be disabled (only the `usage_count >= 2` trigger fires).

15. **WHEN** `graduate` runs, it **SHALL** read the list of recent session IDs from the session store (NOT the `[]` stub at `scheduler.ts:380` — that stub is fixed by SDD-02; SDD-06 depends on SDD-02's fix), **SHALL** load the turns for those sessions from the `message`/`part` tables (for the shadow metric's embedding-delta computation, when `semantic_shift_shadow = true`), **SHALL** iterate over all personas/projects known to the session store (not the hardcoded `project_id: "global"` at `scheduler.ts:437`), and **SHALL** return `{ graduated: number }` where `graduated` is the count of instance memories promoted (including force-promotes per req 14).

### Composite value scoring (SC-5, master §Phase M-3)

16. **WHEN** the `@foxybear/ContextPacker.pack` (SDD-07) or any retrieval path ranks candidate nodes for injection, it **SHALL** compute `score = w_semantic * semantic + w_role * role + w_confidence * confidence + w_provenance * provenance + w_recency * recency + w_usage * usage + w_lifecycle * lifecycle` where the weights are read from `memory.scoring` config (defaults: `w_semantic=0.3, w_role=0.1, w_confidence=0.2, w_provenance=0.1, w_recency=0.1, w_usage=0.1, w_lifecycle=0.1`), and **SHALL** expose a `score(node, query, opts)` function in `src/memory/lifecycle/score.ts` (new file) that returns the composite score in `[0, 1]`.

17. **WHEN** `score` computes the `lifecycle` sub-score, it **SHALL** return `1.0` for `ACTIVE`, `0.5` for `DEPRECATED`, `0.1` for `ARCHIVED`, and `0.0` for `DELETED` nodes (so `is_live`-filtered candidates still get a lifecycle penalty proportional to their stage). The `confidence` sub-score **SHALL** be the node's current `confidence` field (decayed by req 4-11). The `recency` sub-score **SHALL** be `max(0, 1 - age_days / 30)` (linear decay over 30 days from `last_used`). The `usage` sub-score **SHALL** be `min(1, usage_count / 10)` (saturating at 10 uses).

### Scheduler tasks — re-enable + add (SC-6, CC-8)

18. **WHEN** SDD-06 completes, the scheduler **SHALL** register five memory maintenance tasks with English-label intervals matching SC-6: `memory-decay` (interval `hourly`), `memory-consolidation` (existing, interval `daily` — already registered at `scheduler.ts:365`), `memory-graduation` (interval `daily` — replaces the existing `scheduler.ts:411` task using `_config.workforce_sync`), `memory-ttl-pruning` (interval `weekly` — re-enabled, rewired per req 19), and `memory-gc` (interval `weekly`). The task definitions **SHALL** read their schedules from `memory.scheduler.tasks.<name>.interval` config (SC-6), falling back to the defaults above. The scheduler implementation **SHALL** convert English labels (`hourly`/`daily`/`weekly`) to internal cron intervals.

19. **WHEN** the `memory-ttl-pruning` task fires, it **SHALL** call `@foxybear/MemoryLifecycle.prune()` which **SHALL** delegate to the existing `Consolidation.prune` at `consolidation.ts:445` (TTL prune via `Memory.getPrunable` + `Memory.forget`, near-dup merge at cosine > 0.95, 200-entry index cap via `MAX_INDEX_ENTRIES`). The existing inline `Memory.getPrunable + Memory.forget` loop at `scheduler.ts:387-393` **SHALL** be removed and replaced with a single call to `MemoryLifecycle.prune()`. This gives `Consolidation.prune` its first real call site (CC-2).

20. **WHEN** the `memory-gc` task fires, it **SHALL** call `@foxybear/MemoryLifecycle.gc()` (per req 7) and **SHALL** log `{ deleted: number }` at info level. **WHEN** the `memory-consolidation` task fires, it **SHALL** call `@foxybear/MemoryLifecycle.consolidate()` which **SHALL** delegate to the existing `Consolidation.run` at `consolidation.ts:533` with real `recentSessionIds` from the session store (the `[]` stub at `scheduler.ts:380` is fixed by SDD-02; SDD-06 depends on that fix). The `Consolidation.shouldRun()` gate **SHALL** be applied to the `memory-consolidation` task regardless of its interval label.

### Stale penalty replacement (master §Phase M-3)

21. **WHEN** SDD-06 completes, the binary stale penalty at `memory.ts:458` (`if (ageDays > stalePenaltyDays && accessCount < 2) { score *= 0.5 }`) **SHALL** be removed from the `Memory.recall` scoring path, and the `stalePenaltyDays` config field at `config/foxybear.ts:36` (`memory.consolidation.stale_penalty_days`) **SHALL** be marked deprecated with a comment pointing to `memory.decay` as the replacement. The lifecycle-stage-based `lifecycle` sub-score (req 17) subsumes the binary penalty: DEPRECATED nodes already get a 0.5 multiplier, ARCHIVED get 0.1. A memory that is old and rarely used will have decayed to DEPRECATED or ARCHIVED status (per req 5a, 5c), so the binary 0.5× is redundant.

### Config (SC-6, CC-6)

22. **WHEN** the system reads `memory.decay.active_rate`, the decay behavior **SHALL** change accordingly — a test **SHALL** set `active_rate = 0.5` (aggressive decay), run `decay` for one tick against a fixed-correctness fixture, and assert the resulting `confidence` differs from the default `active_rate = 0.01` run by the expected delta. The same test **SHALL** be repeated for `deprecated_rate`, `archived_rate`, `rehearsal_boost`, `deprecated_threshold`, `archived_threshold`, `archive_age_days`, `retention_days`, `decay_model` (set to `prism` — asserts `prism_decay.ts` is dispatched; set to `none` — asserts `decay` is a no-op returning `{ decayed: 0, transitioned: 0 }`), `graduation.force_promote_access_count` (set to 3 — asserts a memory with `usage_count = 3` is force-promoted; set to 0 — asserts force-promote is disabled), and `graduation.semantic_shift_shadow` (set to `true` — asserts `SHADOW_METRIC` events are appended on access; set to `false` — asserts no `SHADOW_METRIC` events). This proves the config is consumed, not just schema'd (CC-6).

23. **WHEN** the system reads `memory.scheduler.tasks.decay.interval`, the decay task's schedule **SHALL** change accordingly — a test **SHALL** set `interval = "daily"` (instead of the default `"hourly"`) and assert the registered `MaintenanceTask.schedule` field reflects the new label. The same test **SHALL** be repeated for `tasks.graduation.interval`, `tasks.pruning.interval`, and `tasks.gc.interval` (each set to a different English label). All interval values **SHALL** be English labels (`hourly`/`daily`/`weekly`) per SC-6; the scheduler implementation **SHALL** convert these labels to internal cron schedules.

### Service interface (SC-5)

24. **WHEN** SDD-06 completes, the `@foxybear/MemoryLifecycle` Effect service **SHALL** be registered as a `Layer.effect` in the daemon runtime, with the interface `{ decay, consolidate, graduate, prune, gc }` (SC-5). Each method **SHALL** return `Effect<{...}>` per SC-5's signatures. The service **SHALL** be composed in the daemon runtime at `src/cli/cmd/serve.ts` (alongside the existing `@foxybear/Memory` and `@foxybear/Embedding` services). The scheduler task handlers **SHALL** resolve the service from the runtime context (not import static functions directly), so the lifecycle logic is testable via layer substitution.

### Abort A5 — coupled-loop sim pathological (SC-11, CC-15)

25. **WHEN** the coupled-loop sim (req 1) fails any criterion after two tuning rounds (per req 2), the implementation **SHALL** trigger abort A5 per master SC-11: freeze lifecycle at TTL + near-dup, ship without the decay engine. Concretely: (a) the `memory-decay` scheduler task remains registered but becomes a no-op that logs "decay engine disabled (abort A5)" at info level and returns `{ decayed: 0, transitioned: 0 }`; (b) the `memory-graduation` task continues to run but only promotes via `usage_count >= 2` and force-promote at 5 (no confidence-based transitions, no semantic-shift); (c) the `memory-ttl-pruning` and `memory-gc` tasks continue unchanged (TTL prune and ARCHIVED-past-retention hard-delete are independent of the decay engine); (d) the `memory.decay_model` config field is locked to `none` and config overrides are ignored with a warning logged at info level; (e) the `STATUS_TRANSITION` events for confidence-based transitions (req 5a, 5b) are NOT emitted (only age-triggered `DEPRECATED → ARCHIVED` per req 5c and soft-delete `* → DELETED` per req 6 emit events). The abort **SHALL** be recorded in the decision log with the failing sim metrics, the two tuning-round parameter deltas, and the final frozen parameter set. The floor per master SC-11: TTL + near-dup + baseline-retrieval injection ships regardless (the decay engine is the only thing dropped; the rest of M-3 stays). Prism promotion (req 3) is blocked until the ESMS convergence proof is verified AND a re-run of the coupled-loop sim with `decay_model=prism` passes the same criteria.

### What is explicitly NOT built

- **ESMS proof / optimal stopping theory** — Prism's formal convergence proof is not ported AND not relied on. Prism is experimental behind `memory.decay_model=prism` (observational only). The default simple exponential + rehearsal needs no proof (a clamped contraction converges). Prism promotion requires ESMS proof verification AND a coupled-loop sim pass with `decay_model=prism`.
- **Value-of-Information retrieval policy** — Prism's VoI retrieval is a candidate for SDD-07 (M-4 packing), not SDD-06. SDD-06 only ports the decay formula + scheduler pattern.
- **Semantic-shift graduation trigger** — semantic-shift is shadow-only (req 13). The graduation trigger is `usage_count >= 2` (parameter-free) with force-promote at 5 (bounds the gating bug). Semantic-shift requires tuning an embedding-delta threshold with no labeled data — shadow metric gathers the training data for a future threshold; zero production risk.
- **Rewrite of `Consolidation.prune` or `graduateMemories` logic** — wrapped, not rewritten. CC-2. The `graduateMemories` signature is unchanged; the `gte(access_count, 2)` filter is preserved.
- **Removal of `memory_topics` SQLite table** — `Memory.getPrunable` continues to read from it; the hypergraph `node` table (SDD-03) is the new primary store, but the legacy path stays during the migration window (SC-8).
- **Multi-user ACL on lifecycle operations** — out of scope (master §Out of scope). Lifecycle operates per persona/project as today.
- **`INVALIDATES` hyperedge type** — not created. Soft-deletes use the `invalidated_by` back-pointer field (SC-2) + `INVALIDATE` event (SC-9) per master SC-3. No new hyperedge type is introduced.
- **Conflict detector** — SDD-09 (M-5, deferred post-M-6). SDD-06 only provides the soft-delete mechanism (req 6, 8) that SDD-09 will invoke. The coupled-loop sim uses synthetic contradictions (injected at known tick boundaries) to test the conflict-interaction surface without depending on SDD-09.
